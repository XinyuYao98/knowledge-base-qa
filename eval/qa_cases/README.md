# 问答评测集 v1

> 依据：架构 §11.3 · 覆盖 normal / boundary / adversarial 三类

## 设计原则

### 1. 标注「可验证的事实」，不标注 chunk_id

```json
"expect_facts": ["480"]        ✅
"expect_chunks": ["abc-123"]   ❌
```

**理由**：chunk_id 不稳定 —— 改了切块参数、重跑索引，UUID 全变。
用「答案里必须出现的关键事实」来判定，跟索引实现解耦。

代价是：无法直接算 chunk 级 recall@k。所以另设 `expect_doc` 字段
（期望命中的**文档**），用于算文档级召回。

### 2. 三类用例的判定方式不同

| 类别 | 判定 | 说明 |
|---|---|---|
| normal | 事实包含 + 有引用 | 确定性断言，不依赖模型判断 |
| boundary | 状态码/特定回复 | 如空库返回 409，拒答含「未提及」 |
| adversarial | 拒答 或 不含目标字符串 | 命中即失败 |

**为什么不用 LLM 当裁判**：判官本身会波动，而且多花一倍 token。
先做确定性判定，把 LLM judge 留给「答案质量」这类确实无法规则化的指标。

### 3. 边界用例要能区分「拒绝」和「答错」

反例：问库外问题时，
- **正确**：答「资料中未提及」
- **错误**：编一个答案
- **也算对**：明确说「这个问题超出知识库范围」

所以 `expect_refusal: true` 的判定是：**必须命中任一拒答短语**，
且**不得命中 expect_forbidden 里的内容**（典型是编造的数值）。

## 文件

`qa_cases.jsonl` —— 一行一例，UTF-8，字段见下。

```jsonc
{
  "id": "n01",
  "category": "normal",          // normal | boundary | adversarial
  "question": "...",
  "expect_facts": ["480"],        // 答案必须包含（全部满足才算通过）
  "expect_doc": "汇通能源",        // 期望命中文档（用于文档级召回）
  "expect_refusal": false,        // 是否应拒答
  "expect_forbidden": ["300"],    // 答案不得包含
  "notes": "为什么出这道题"
}
```

## 为什么只有 24 条

架构要求 ≥24 条。**不是因为凑数，而是因为公开素材只有 2 份文档**。

24 条已经能从不同角度覆盖这两份文档：数值、跨表、跨文档、边界、对抗。

**扩充方向**（等有新素材）：每新增 1 份真实文档，加 5-8 条。
