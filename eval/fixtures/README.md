# 测试素材说明

## 为什么要有这个目录

解析层是这个项目的质量地基（架构文档 §6）。但**没有真实素材，就无法验证解析质量**。

`pytest` 能告诉你"代码没崩"，不能告诉你"解析对了"。要回答后者，必须有：
文件 + 明确的期望输出 + 自动断言。

---

## 三层结构

```
eval/fixtures/
├── public/      公开真实文档 —— 测「解析得对不对」
├── synthetic/   程序合成的刁钻文件 —— 测「边界崩不崩」
└── private/     个人文档 —— 只本地验证，永不提交
```

### `public/` —— 公开真实文档

**用途**：验证真实版式下的解析质量。合成文件永远比真实文档"干净"。

**来源要求**：必须是**公开发布、可合法获取**的文件。当前包含：

| 文件 | 来源 | 覆盖的测点 |
|---|---|---|
| `上海汇通能源股份有限公司2026年第三季度报告.pdf` | 上市公司公开披露 | 12 页、13 处表格、最大 43 行×3 列（财务三表） |
| `2025年全国科技经费投入统计公报 - 国家统计局.html` | 国家统计局公开页面 | 6 张表（含 46 行行业表、33 行地区表）、649 段正文 |

**HTML 是浏览器"网页另存为"的产物**，带一个 `_files/` 资源目录（31 个文件：CSS/图片/下载附件）。
解析器需要：
1. 剔除 `<script>` / `<style>`
2. 剔除导航、页脚、分享按钮等噪声
3. 只取正文容器内的内容

> 这是**真实的脏数据**，比手写干净 HTML 更能暴露问题。

### `synthetic/` —— 程序合成

**由 `scripts/make_fixtures.py` 生成**，不要手改。改了就重新生成。

| 文件 | 测什么 | 为什么危险 |
|---|---|---|
| `xlsx_merged_cells.xlsx` | 合并单元格 + 双行表头 | 合并单元格只在左上角有值，其余是 `None`。不处理会导致"华南"那行的数字失去区域归属 |
| `xlsx_multi_tables.xlsx` | 空行分隔的两张逻辑表 | 不识别表边界会把两张表混成一张，表头串味 |
| `pdf_scanned_no_text.pdf` | 扫描件（无文字层） | **最危险**：返回空字符串并当成功，用户会以为"这文档没内容" |
| `pptx_notes_heavy.pptx` | 备注远多于正文 | 不读 `notes_slide` 会丢掉 80% 信息，检索只能命中无意义标题 |
| `txt_gbk_chinese.txt` | GBK 编码 | 识别错不报错，直接给乱码 |
| `empty.txt` | 0 字节文件 | 塞空 chunk 进索引会污染 BM25 的文档长度统计 |

**共同点**：这六种情况**错了都不会报错**，只会静默给出错误结果。这比崩溃危险得多。

### `private/` —— 个人文档

**这个目录的内容不会提交到仓库**（见 `.gitignore`）。

**用途**：用你自己的真实文档跑一遍，看解析效果。真实工作文档的版式复杂度往往超出预期。

**使用规则**：
1. 自己复制文件进来
2. 手动跑解析，肉眼检查
3. **用完删掉**

**绝对不能放进 `public/`**：简历、离职证明、身份证明等含 PII 的文件一旦推到公开仓库，等于主动泄露。

## 期望输出在哪

`eval/expected/{文件名}.json`，与 `synthetic/` 中的文件一一对应。

```json
{
  "file": "xlsx_merged_cells.xlsx",
  "format": "xlsx",
  "test_focus": "合并单元格 + 双行表头 + 行级切块",
  "expected_table": { ... },
  "assertions": [
    "存在包含 '华东' 与 '1280.5' 的 chunk",
    "每个数据行 chunk 都重复携带表头（Q1/Q2 字段名）"
  ]
}
```

**关键设计**：期望输出由生成脚本**同步产出**，不是手写的。

> 手写期望值最容易和文件脱节：改了文件忘了改期望，或者反过来。
> 两者同源生成，就永远不会不一致。

---

## 怎么用

```bash
# 重新生成合成样例（改脚本后必须跑）
python scripts/make_fixtures.py

# 跑解析层测试（P2 之后可用）
cd backend && pytest tests/parsers -v
```

## 待补充的素材

按架构 §6 的解析矩阵，目前还缺这几种真实样例：

| 缺什么 | 为什么需要 |
|---|---|
| **双栏排版 PDF** | pypdf 的阅读顺序是这条技术路线最大的风险点 |
| 带合并单元格的真实 Excel | 合成的只测了规则化的合并，真实表格更乱 |
| 扫描件 PDF（真实） | 合成的只有一张纯白图，真实扫描件有倾斜、噪点 |
| DOCX 含表格与图片 | 目前没有真实 Word 样例 |

**这几项如果一直补不上，就应该在 README 里如实写明"未验证"。**
写"未验证"不丢人，写"已验证"但实际没验证才丢人。
