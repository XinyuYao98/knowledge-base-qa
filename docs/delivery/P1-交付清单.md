## 二、RLS 验证的 11 项检查（这才是重点）

`python scripts/verify_rls.py`

| # | 检查内容 | 为什么重要 |
|---|---|---|
| 1 | 应用角色 `kbapp` 不是 superuser | superuser 完全绕过 RLS |
| 2 | 应用角色无 BYPASSRLS | 有它等于关掉整个隔离机制 |
| 3 | alice 只看到自己的 1 个库 | 基本隔离 |
| 4 | bob 用 alice 的 user_id 直接查 → 0 条 | 横向越权 |
| 5 | **未设置 app.user_id → 0 条** | 安全默认值：忘记设就查不到 |
| 6 | documents 同样返回 0 | 覆盖所有业务表 |
| 7 | 不存在的 uuid → 0 条 | 防御脏数据 |
| 8 | alice 无法以 bob 身份插入 | WITH CHECK 生效 |
| 9 | 超管仍能看到全部 | 运维需要（第 10 条的前提） |
| 10 | 应用角色不能建表 | DDL 权限隔离 |
| 11 | 策略数量 = 9 | 与设计一致 |

> **第 5 条是整个隔离机制的核心。**
> 如果 RLS 策略写错了，错误方向必须是「查不到」，而不是「查到全部」。
> 这一条验证的正是错误方向。

## 三、两个 Windows 专有坑（都已在代码里处理）

### 坑 1：psycopg 不支持 ProactorEventLoop

```
InterfaceError: Psycopg cannot use the 'ProactorEventLoop' to run in async mode
```

**根因**：Python 3.13 的 `asyncio.run()` 用 `loop_factory` 建循环，**不读全局策略**。
所以 `asyncio.set_event_loop_policy(WindowsSelectorEventLoopPolicy())` 之后，
`asyncio.run()` 仍然建 ProactorEventLoop —— 策略设置被静默忽略。

**这解释了为什么我试了两次「设置策略」都失败。**

**修复**：
- `app/core/platform.py` 提供 `selector_loop_factory()` 与 `run()`
- `scripts/dev.py` 用 `uvicorn.Server` 编程接口 + 自建 selector 循环
- `make dev` 已改为调 `scripts/dev.py`

### 坑 2：engine 不能是模块级单例

模块导入时创建 engine，但真正的 TCP 连接在首次使用时才建立。
如果那时事件循环已经不对，连接就建不起来。

**修复**：`get_engine()` 延迟初始化 + 建连接前做循环兼容性自检（fail fast）。

## 五、Docker 镜像加速

`pgvector/pgvector:pg16`（631MB）从 Docker Hub 拉取时**卡死 11 分钟无进展**。

解决：用 `docker.1ms.run` 镜像源拉取后重打 tag，45 秒完成。

```bash
docker pull docker.1ms.run/pgvector/pgvector:pg16
docker tag docker.1ms.run/pgvector/pgvector:pg16 pgvector/pgvector:pg16
```

`docker-compose.yml`（生产编排）里的 `chromadb/chroma:1.5.9` 首次拉起也会遇到同样问题，
已在此记录。
