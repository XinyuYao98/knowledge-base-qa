## 三、三个实测踩到的坑

### 坑 1：系统代理劫持 localhost 请求

环境里有 `HTTP_PROXY=http://127.0.0.1:52768`。httpx 默认 `trust_env=True`，
**连 `127.0.0.1:1234` 都会走代理**，结果 `ReadTimeout`。

实测对比：

```
trust_env=True   → ReadTimeout（5 分钟无响应）
trust_env=False  → HTTP 200，1.5s
```

**修复**：所有模型客户端统一 `trust_env=False`（配置项 `LLM_DISABLE_PROXY`）。

> 这个问题很隐蔽：curl 能通、embedding 能通，只有 chat 超时。
> 因为 chat 请求体大、耗时长，代理更容易在这个场景暴露。

### 坑 2：推理模型的思考吃光 token 预算

`qwen/qwen3.5-9b` 实测：

| max_tokens | 思考 tokens | 回答内容 | 耗时 |
|---|---|---|---|
| 20 | 20 | **空** | 1.5s |
| 300 | 300 | **空** | 27.5s |
| 1500 | 连续思考 | **空** | 86s |

**它不会自己停下来。** `/no_think` 指令也无效（仍消耗满额 thinking tokens）。

**解法**：预填充 assistant 消息（`{"role":"assistant","content":"根据资料，"}`）

| 方式 | 思考 tokens | 耗时 | 结果 |
|---|---|---|---|
| 无预填充 | 300+ | 27-86s | 空回答 |
| **有预填充** | **0** | **0.7-2s** | 正常回答 |

**提速约 40 倍，且不再出现空回答。**

### 坑 3：引用写法不止一种

模型实测会写：

```
[1]        ← 单引用
[1][2]     ← 多引用
[1-5]      ← 区间（第一次跑时就是这里失败）
[1,2]      ← 逗号
```

第一版正则只认 `[数字]`，`[1-5]` 提取不到 → 误判为「引用无效」。

而且拒答场景（`资料中未提及 [1-5]`）**本来就不该要求引用** ——
没有结论可归属，硬标编号反而是编造。

**修复**：
- 正则支持区间与逗号
- 拒答措辞命中时，允许无引用

## 四、顺带发现的配置错误

LM Studio 里的 embedding 模型 ID 是 `text-embedding-qwen3-embedding-4b`，
配置里写的 `qwen3-embedding-4b` 也能调通（LM Studio 不校验 id），
但**以服务端 `/v1/models` 返回为准**才对。

已改正，并在启动时加了模型存在性检查：

```
Embedding: text-embedding-qwen3-embedding-4b
  ✓ 服务可达, 模型存在=True
```

模型不在列表里会明确报错，而不是等着后面向量维度对不上。
