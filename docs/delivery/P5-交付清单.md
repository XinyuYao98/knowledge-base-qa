## 三、P4 遗留问题已解决

P4 交付时标注的 ⚠️：

> `users` 表受 RLS 保护，应用角色连注册用户都插不进去。

**解决方式**：`auth_register()` SECURITY DEFINER 函数（Q1 选 A）。

### 用 4 个测试证明解法正确

| 断言 | 意义 |
|---|---|
| 应用角色直接 INSERT → 被 RLS 拒 | **隔离仍然生效，没有倒退** |
| 调 `auth_register` → 成功 | 解法有效 |
| 重复注册 → 返回 None 而非抛异常 | 业务层能返回 409 而不是 500 |
| 无身份时 `SELECT count(*) FROM users` → 0 | **提权没有被滥用** |

第 4 条尤其重要：`SECURITY DEFINER` 只把「插入 users」这一件事的权限提起来，
调用方**读不到**其他用户。

## 四、限流的实测行为

双维度阈值：

| 维度 | 阈值 | 实测 |
|---|---|---|
| 用户名 | 5 次 / 15 分钟 | **第 6 次触发 429** |
| IP | 10 次 / 1 分钟 | 换账号扫号时触发 |

**发现一个反直觉的事实**：固定猜一个账号时，**先撞上的是用户名维度**（5 次 < 10 次）。

这不是 bug，正是双维度的意图 —— 攻击者换 IP 打同一账号也挡得住。
我最初的测试按 IP 阈值断言，结果失败；改成分开验证两个维度后才对。

`429` 响应带 `Retry-After`。

## 五、实测踩到的三个问题

### 1. `ValueError` 冒到全局异常处理器变成 500

`validate_password_policy()` 抛的是 `ValueError`，不是 `AppError`。
弱密码注册直接 500，用户看到一个未处理异常。

**修复**：service 层捕获并转成 `AppError("weak_password", ..., 400)`。

**这类问题的共性**：底层函数用标准异常，上层假设它是业务异常。
P6 写检索时还会遇到，要成惯例检查。

### 2. 抛异常前设在 `response` 上的 header 全丢

```python
for k, v in limit.headers().items():
    response.headers[k] = v     # ← 白设
raise AppError("rate_limited", ..., 429)
```

FastAPI 走 `exception_handler` 生成**新响应**，之前设的 header 不保留。
429 返回了，但 `Retry-After` 没有。

**修复**：放进 `AppError.detail`，由全局异常处理器写 header。

### 3. Redis 不可用时测试卡几分钟

限流是 fail-open（Redis 挂了放行），但每次请求都会等 2 秒超时。
Redis 没启动时，整批测试串起来要等几分钟才结束。

**修复**：加 session 级 fixture，**Redis 不可用直接 skip**，而不是慢慢超时。

**这是上一轮 Docker 关闭时踩到的**，当时整批测试卡死没有输出。

## 六、两个设计决策的记录

### JWT 只放 `sub`，24 小时，无 refresh（Q2）

`sub` 存 user_id 而不是 username：**username 会变，user_id 不会**。
不放 refresh token 是因为它要多出「刷新端点 + 存储 + 撤销」一整套，
而这一期的价值在「能跑通」。

### 上传只做直传（Q4）

分片是给 500MB 年报表准备的场景，现在**没有真实文件能压测**。
`MAX_SINGLE_FILE_BYTES` 默认 200MB，超限返回 413。
分片延后到有真实需求时再做。

### 删除校验放后端（Q4）

前端弹框输库名只是 **UX**（防手滑）。
后端必须再校验 —— 否则任何能构造请求的人都能绕过。
测试 `test_delete_wrong_confirm` 证明：名字不符时库还在。

## 七、已知问题

| 问题 | 影响 | 处理 |
|---|---|---|
| **无 refresh token** | 24 小时后需重新登录 | 按 Q2 决策接受 |
| **限流是固定窗口** | 窗口边界处可能通过 2 倍请求量 | demo 可接受；生产换滑动窗口 |
| **限流 fail-open** | Redis 挂了不挡爆破 | 已记录；生产应改 fail-closed |
| **不信任 X-Forwarded-For** | 部署在反向代理后所有请求共享一个 IP | 部署时需显式配置 |
| **分片上传未实现** | >200MB 文件传不了 | 按 Q4 决策延后 |
| **未做邮箱/手机号** | `users` 表无 email 字段 | 架构原本就只做用户名 |
| **上传响应 202 但无进度** | 前端需轮询 `/documents` | 已有该端点 |
| **`login_attempts` 只增不减** | 长期运行会堆积 | 与 `query_logs` 同类，README 写明 |
