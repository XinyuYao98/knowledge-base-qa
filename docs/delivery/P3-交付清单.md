## 三、核心能力与实测

### 1. 单阶段重跑：这是 P3 存在的理由

```
$ make reprocess DOC=pdf-demo STAGE=chunk

从阶段: chunk
将清除: ['chunk', 'embed']

阶段执行：
  parse  复用（指纹未变）      ← 关键：没有重解析 PDF
  chunk  执行  0ms
  embed  执行  52ms
```

**价值**：调切块参数时，128 页 PDF 重解析 779ms，只重切块 52ms。
改一次参数可能要试十几次，这个差距会累积。

### 2. 指纹决定复用

```
parse 指纹 = hash(文件内容sha256 + 解析参数)
chunk 指纹 = hash(parse指纹 + 切块参数)
embed 指纹 = hash(chunk指纹 + 模型配置)
```

改切块参数 → `parse` 复用，`chunk` 与 `embed` 重跑。
改模型 → 只有 `embed` 重跑。

**实测验证**（`test_chunk_param_change_only_reruns_downstream`）：
monkeypatch 改 `MIN_CHUNK_CHARS`，断言 `parse` 在 reused、`chunk` 在 run。

### 3. 真实文档的管道表现

| 文档 | 解析 | 切块 | 向量 | 块数 | 表格行块 |
|---|---|---|---|---|---|
| 汇通能源三季报 PDF | 779ms | 0.4ms | 52ms | **403** | **379** |
| 统计局公报 HTML | 92ms | 0.2ms | 25ms | 200 | — |
| PPT 备注 | 8ms | 0ms | 0.5ms | 3 | — |

**PDF 从 32 个解析块切出 403 个块**，其中 379 个是表格行块——说明
表格行级切块（§6.1）在真实财务表上生效了。

### 4. 健康分

```
score = 1 - [0.4×丢块占比 + 0.3×有告警 + 0.3×每页字符<200]
```

| 文档 | 得分 | 因子 |
|---|---|---|
| 汇通能源 PDF | 1.00 | 每页 1725 字，无告警，无丢块 |
| GBK TXT | 1.00 | 编码猜测告警不扣分（不影响内容完整性） |

## 四、修掉的三个真实 bug

### bug 1：`embed` 阶段永远被记成「已执行」

```
out.stages_run: ['embed']        ← 明明复用了
out.stages_reused: ['parse', 'chunk']
```

`_do_embed()` 只返回向量，没返回「是否复用」，主流程无条件记 `stages_run`。

**后果**：日志显示全部复用，但耗时统计把它算成执行，性能对比全错。
**修复**：改为返回 `(vectors, reused)`。

### bug 2：相对路径 `./data` 按 cwd 解析，产生两套数据

```
项目根跑 → 项目/data/staging/
backend/ 跑 → backend/data/staging/     ← 同一份数据，两个位置
```

**后果**：管道在项目根写入，读质量报告时在 backend 下读不到，报「文件不存在」。
**修复**：`storage_root` 与 `chroma_path` 改为**始终相对项目根**解析。

### bug 3：健康分读错字段路径，低密度检测静默失效

真实结构是 `stages.parse.detail.char_count`，
但代码读 `stages.parse.char_count` → 拿到 `None` → `chars_per_page` 恒为 0。

**后果**：扫描件永远不会被标记。**最危险的一类 bug：不报错，只是结论错了。**
**修复**：按 `detail` 内路径读取，并保留平铺结构的兼容。

**为什么没被测试抓到**：我的测试 mock 用的是平铺结构，与真实不一致。
已补 `TestHealthRealStructure`，直接用真实 `meta.json` 结构做断言。
