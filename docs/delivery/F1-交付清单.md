### SSE 验收的细节（这是本期最关键的一条）

用一个 mock 服务端把字节流**每 7 字节切一刀**，必然切在汉字（3 字节）中间：

```
网络字节块数: 52
解析出事件数: 6
事件顺序: meta → delta → delta → delta → done → end
拼接后文本: "一线城市住宿标准是480元"
```

52 次任意切分、多次切断汉字，解析结果完全正确。
说明架构 §4.2 列的三个边界（分帧不完整、多字节截断、done/end 区分）都处理对了。

## 三、修掉的阻塞项

### 1. CORS 三处不一致

```
.env            → http://localhost:3002
config 默认值   → http://localhost:3000
Vite 实际端口   → 5173
```

三个数字互不相同，前端第一个请求就会被浏览器拦。

**修法**：三处统一为 `http://localhost:5173,http://127.0.0.1:5173`。

**为什么 `127.0.0.1` 也要放行**：浏览器按「协议+主机+端口」三元组判定同源，
`localhost` 与 `127.0.0.1` 视为不同源。实测两者都会出现。

### 2. `openapi-typescript` 与 TypeScript 6 不兼容

Vite 脚手架装的是 TS **6.0.3**，而 `openapi-typescript@7.13.0` 的 peer 是 `^5.x`。

**没有用 `--force` 硬装**（会让类型不兼容的问题推迟到构建期才暴露），
而是降到 `typescript@~5.9.0`。Vue 3.5 对 TS 5 的支持最成熟。

### 3. shadcn-vue 官方 CLI 在本机不可用

`npx shadcn-vue init` 报：

```
Failed to fetch from registry: https://shadcn-vue.com/r/styles/index.json
```

但同一个 URL：`curl` 200、Node 原生 `fetch` 200（590ms）、3s 超时内也 200。
**网络没问题，是 CLI 内部 HTTP 客户端的问题。**

**不绕过风险，改绕过工具**：写 `scripts/install-shadcn.mjs`，
用 `curl` 拉注册表 JSON，按 `files[]` 落盘。

### 4. 组件源码里的 import 路径要重写

注册表中的组件写的是 `@/registry/new-york/ui/button`，CLI 自己运行时会改写，
我用脚本落盘就绕过了这一步，导致构建报：

```
Cannot find module '@/registry/new-york/ui/button'
```

已在安装脚本里加正则重写，并**在脚本注释里写明这是踩过的坑**。

## 四、实测踩到的环境问题

### 8080 端口被占用

本机 8080 有其它进程在监听，后端只能起在 8090。

**处理**：不做硬编码，加 `VITE_PROXY_TARGET` 环境变量：

```bash
# frontend/.env.development
VITE_PROXY_TARGET=http://127.0.0.1:8090
```

同时给 `vite.config.ts` 加了 `loadEnv` 读取，换端口不用动代码。

### 5173 / 5174 被残留进程占用

多次启动测试后，旧 Vite 进程没退干净，导致新实例跳到 5175。
**这是测试过程产生的脏状态，不是项目问题**，已清理。

### `localhost` 被系统代理拦截

本机有 `HTTPS_PROXY` 环境变量，`curl http://localhost:5173` 会被代理转走并返回 502。
验证时统一加 `--noproxy "*"`。

**对开发无影响**（浏览器不走这个代理），但写进 README 避免下次误判。

## 五、发现的缺口（记录，本期不修）

### 后端缺「删除文档」「重建索引」端点

架构 §7.3 写了这两项，但核实 `backend/app/api/routes/documents.py`：

```python
@router.post("", status_code=202)   # 只有上传
```

**没有** `DELETE /{doc_id}`，也没有重建索引接口。

**影响 F3**：文档表格的「操作」列做不出来。
**处理**：F3 开工前要么补后端接口，要么把这列从范围里去掉。**需要你在 F3 前定。**

### 库里没有任何知识库

`SELECT count(*) FROM knowledge_bases` → **0**。

所以 SSE 只能用 mock 验证，真实端到端要等 F2（注册登录）+ F3（上传）之后。

## 七、给后续三期的提醒

1. **F2 前先确认 `username` 长度取 3–20**
   后端 Pydantic 允许 3–32，但 DB 约束是 3–20，21–32 会触发 500。
   架构 §7.1 推荐把 `RegisterRequest.max_length` 改成 20。

2. **F3 前确认文档删除/重建索引是否补后端接口**

3. **后端改接口后必须跑 `npm run gen:api`**，并把 `openapi.json`
   与 `generated.d.ts` 一起提交。

4. **页面里不准直接 `fetch`**，一律走 `api/http.ts`。
