```python

MARGIN   = 28       # 左右边距
GUTTER   = 24       # 列间距
COL_W    = (680 - 28*2 - 24*2) // 3   # = 192  单栏宽
```


## 五、改图规则（避免再次错位）

| 要改什么 | 改哪里 | 连带影响 |
|---|---|---|
| 换文案 | 直接编辑 `<text>` 内容 | **不影响任何坐标**（只要字数不超框宽） |
| 加/删一个节点 | 改 `BOX_H` 或 `GAP`，重算四行 y | 索引卡高度 `= 46*4 + 12*3`，必须同步 |
| 改栏宽 | 改 `COL_W`，重算 `X2/X3` | 索引卡宽、框宽、箭头起止点全部重算 |
| 改配色 | 替换上表色值 | 无 |
| 改画布宽 | 改 `CANVAS_W` 与 `viewBox` | 全套重算 |

**自检脚本**（改完跑一遍）：

```bash
python scripts/check-diagram.py
```

它会验证：三栏等宽 / 等距 / 边距对称 / 索引卡与两栏同顶同底 / 四条均分 / 箭头端点贴合框边。

## 六、文案层级约定

每个节点都是「**动作 + 属性标签 + 价值说明**」三段式：

```
上传文档          9 类格式      ← 右上角：名词性属性，不是动词
报告 / 手册 / 台账               ← 副标题：用户能理解的具体说明
```

**右上角 8 个标签全部是名词性属性**：9 类格式 / 结构还原 / 语义可检索 / 可诊断 / 多轮 / 只在本库 / 依据驱动 / 带来源。

改文案时保持这个规律：**右上角写“是什么”，副标题写“有什么用”。**

## 七、术语层级

| 层级 | 用词 | 例子 |
|---|---|---|
| 分栏（英文） | BUILD / STORE / QUERY | 抽象阶段名 |
| 分栏（中文） | 知识沉淀 / 知识索引 / 提问获答 | 用户能懂的说法 |
| 跨栏箭头 | **入库 / 召回** | RAG 标准术语 |
| 节点内 | 语义可检索 / 双路召回 / 依据驱动 | 实现方式 |

**不要用「写入 / 读出」**——那是数据库 I/O 的口语表达，不是 RAG 术语。
